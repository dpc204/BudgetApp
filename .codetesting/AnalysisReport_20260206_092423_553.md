## Budget.Client.Tests.csproj - Budget.Client.Tests.Services.EnvelopeDataServiceTests.GetCategoriesForSelect_WithMultipleCategories_ReturnsAdaptedCategories
- **Confidence**: High
- **Test File**: Budget.Client.Tests\Services\EnvelopeDataServiceTests.cs
- **Bug Location**: Budget.Client\Services\EnvelopeDataService.cs@66

### Analysis
The GetCategoriesForSelect method uses Mapster's Adapt to map from CategoryDto to Cat, but these classes have mismatched property names: CategoryDto.Name vs Cat.CategoryName. Mapster's convention-based mapping requires matching property names, so CategoryName remains empty. The correct approach (shown in LoadEnvelopeDataAsync at line 25) is to manually map: 'CategoryName = c.Name'. The test is correct in expecting CategoryName to be populated.

### Suggested Fix
In C:\Repos\BudgetApp\Budget.Client\Services\EnvelopeDataService.cs, the GetCategoriesForSelect method needs to manually map properties instead of relying on Mapster. Replace lines 61-69 with:

```csharp
public List<Cat> GetCategoriesForSelect()
{
  var cats = api.GetCategoriesAsync();
  var rslt = cats.Result.Select(c => new Cat 
  { 
    CategoryId = c.CategoryId, 
    SortOrder = c.SortOrder, 
    CategoryName = c.Name, 
    CatType = c.CatType 
  }).ToList();
  return rslt;
}
```

Alternatively, if the 'All' category should be included (as suggested by the commented-out line 65), prepend it:

```csharp

  rslt.AddRange(cats.Result.Select(c => new Cat 
  { 
    CategoryId = c.CategoryId,

    CategoryName = c.Name, 
    CatType = c.CatType 
  }));

```

Note: The current test expects 3 items without the 'All' category, so the first fix is appropriate for the test as written.

## Budget.Client.Tests.csproj - Budget.Client.Tests.Services.EnvelopeDataServiceTests.GetCategoriesForSelect_WithSingleCategory_ReturnsSingleAdaptedCategory
- **Confidence**: High
- **Test File**: Budget.Client.Tests\Services\EnvelopeDataServiceTests.cs

### Analysis
The production code uses Mapster's .Adapt<List<Cat>>() method to map CategoryDto to Cat objects. However, CategoryDto has a 'Name' property while Cat has a 'CategoryName' property. Mapster only maps properties with identical names by default, so CategoryName remains as empty string. The correct mapping is demonstrated in LoadEnvelopeDataAsync (line 25) where it explicitly maps: CategoryName = c.Name. The test correctly expects CategoryName to be 'Food' but gets an empty string due to this mapping issue.

### Suggested Fix
The GetCategoriesForSelect() method at line 61-69 in C:\Repos\BudgetApp\Budget.Client\Services\EnvelopeDataService.cs needs to be fixed. Replace the Mapster .Adapt() call with explicit property mapping like in LoadEnvelopeDataAsync. The fixed method should be:

```csharp

  { 
    CategoryId = c.CategoryId, 
    SortOrder = c.SortOrder, 
    CategoryName = c.Name, 
    CatType = c.CatType 
  }));

```

Alternatively, configure Mapster to map Name to CategoryName, but the explicit mapping approach is more maintainable and consistent with the existing code in LoadEnvelopeDataAsync.

## Budget.Client.Tests.csproj - Budget.Client.Tests.Services.EnvelopeDataServiceTests.GetCategoriesForSelect_WithSpecialCharacters_PreservesSpecialCharacters

### Analysis

```csharp
public List<Cat> GetCategoriesForSelect()

```
